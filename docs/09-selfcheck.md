## 门 1 · `src/verify.py` — 几何与像素

重新**打开产出的文件**验，不信内存里的对象。

| 检查 | 方法 | 抓到过什么 |
|---|---|---|
| 图框尺寸 | 重新解析 PDF，量外框 | matplotlib 画布被 `finalize()` 改过宽高比 |
| 内容 1:1 | 量图内已知长度 / 标称长度 | 页面尺寸对但内容被拉伸 |
| 灯具数量 | 数 DXF 里的 `INSERT` | 符号没插进去 |
| 零重叠 | 逐对求包围盒相交 | 文字压文字、文字出框 |
| **灯具朝向** | 多边形变换到图纸坐标，沿 Y 切片比两端宽度 | **全台灯 180° 反了** |
| 桁架腹杆 | 600dpi 裁块，数竖向墨柱，合并相邻段 | 桁架画成空心方块 |
| 管线空心 | 内部平均墨密度 < 0.12 | 管线里画了多余内线 |
| 墨密度 | 全图 / 局部最密 | 局部糊成一片 |

### 灯具朝向这条为什么重要

GDTF 符号的**镜片在 -Y**（实测 fresnel -Y 均宽 237.6 / +Y 186.2）。
代码一度按 +Y 当前方，`rotation = aim - 90`，结果全台反 180° —— 图上所有灯都对着观众。

而**其它检查全部通过**：灯确实画出来了，数量对，不重叠，墨密度正常。
只有把「朝向」当成一条独立断言才抓得住。

```python
# 把符号多边形按 blockref 的 rotation/scale 变换到图纸坐标
pts = [(ins.x + sc*(x*cos(r)-y*sin(r)), ins.y + sc*(x*sin(r)+y*cos(r)))
       for poly in polys for x, y in poly]
# 沿世界 Y 切片，比两端横截宽度 —— 宽端是镜片
lens_y = +1 if hi > lo else -1
assert (lens_y > 0) == (sin(radians(aim)) > 0)
```

## 门 2 · `tools/golden.py` — 黄金图回归

`verify.py` 检查的是「符合我写的规则」。这些都对，但都是**我定义的规则**。
它们抓不到「规则全过，但看起来就是不像」。

参考图（`brief/reference/*.pdf`，Vectorworks 画的 NIDA A1 图纸）是唯一的外部标准。

### 比什么

不是整张图（版式不同，整图 SSIM 没意义），是**构件级切片**：

| 构件 | 参考图坐标 (mm) | 当前出图坐标 (mm) |
|---|---|---|
| `truss_cell` | 54.19, 58.3 → 66.5, 71.5 | 120, 421.5 → 133, 435.5 |
| `truss_run` | 150, 58 → 174, 72 | 300, 421.5 → 324, 435.5 |
| `fixture_block` | 700.6, 515 → 745, 545 | 205, 172 → 249, 202 |

坐标是用**墨迹密度探测**实测的，不是猜的：
参考图桁架第 1 行 y≈59–71，x 从 54.2 开始，节距 11.77mm；
当前出图 LX2 桁架 y≈429，x 从 55 开始，同一节距。

### 阈值 0.60 怎么来的

同一构件两次渲染的 SSIM 在 0.97 以上；不同实现之间在 0.55–0.85。
所以 0.60 是「形状本身错了」的界线，不是「渲染差异」。

### ★ 反假通过：MIN_INK

早先版本坐标标错，裁到**空白区域**，两块全白 → SSIM = 1.0 → **假通过**。

现在加了硬断言：任一裁块墨密度低于 1% 直接 FAIL，并说明是坐标错了。

```
[FAIL] 黄金图：crop is blank, coordinates are wrong (this is NOT a perfect match):
       truss_cell(参考墨密度 0.0339 / 当前 0.0000)
```

## 门 3 · `src/hsc.py` — HSC 合规

HSC 失分很少是「图画得不好」，而是**材料不齐或规格不对**。
这些全部可机检。

| 检查 | 依据 |
|---|---|
| rationale 300 词上限 | NESA：「超出部分直接忽略」 |
| rationale 四段式完整 | DoE 官方模板 intent/moments/elements/audience |
| rationale 无技术词 | 要 director's concept，不是设备清单 |
| 平面图 ≥ 2 场景 | 「two key scenes」 |
| 比例 1:25 | 硬性规格 |
| 两个场景对比够大 | marker：「对比要足够大，才能展示创作广度」 |
| 表演区已标出 | 「明确标出关键表演区」 |
| 每盏灯有 purpose | 「说明每盏灯覆盖的区域」 |
| Cue sheet 存在 | Execution 标准 |
| Running script 与 cue 一一对应 | 「提示本和/或 cue sheet 可能不完整」是 3–4 分档 |

## 各校验器的交叉引用

```
qc.py       数据层：重号/通道冲突/未定义色片/缺 beam
  ↓
cues.py     Cue Sheet 内部 + 与 rig.yaml 的色片一致性
running.py  Running Script 与 Cue Sheet 的编号/顺序一致性
rationale.py 词数与段落完整性
  ↓
verify.py   出图后几何 + 像素
golden.py   与参考图的视觉相似度
  ↓
hsc.py      材料完整性与 NESA 规格
```

**每一层失败都会非零退出。** 这是设计上的选择：宁可没有文件，
也不要一张看起来对、实际错的图。

---

## 已知的检查盲区（诚实清单）

1. **`purpose` 字段只检查非空，不检查内容是否合理。**
   写 "FACE F1" 和写 "asdf" 都能过。
2. **两个场景的「对比度」是数量化指标，不是质量判断。**
   色片差 3 项能过，但差得有没有戏剧意义，机器不知道。
3. **黄金图只比三个构件。** 图签、右栏表格、注释块都没有基准。
4. **没有验证 DXF 导入 Vectorworks 后是否还是灯具对象。** 未测，别当已知事实。
5. **装裱无玻璃、原创声明** 两项不可机检，只能人工确认。
